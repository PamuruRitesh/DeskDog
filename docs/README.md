# 📚 DeskDog Documentation

Welcome to the DeskDog engineering documentation.

This documentation is not only intended to explain **how DeskDog is built**, but also **why it is built this way**.

DeskDog is developed as an educational embedded systems project where every architectural decision, software component, and hardware interface is documented alongside its implementation.

The goal is to learn professional embedded software engineering by building a real project from the ground up.

---

# Documentation Philosophy

Every lesson in DeskDog follows the same engineering process:

1. Understand the problem.
2. Learn the underlying concept.
3. Design the architecture.
4. Implement the solution.
5. Test the implementation.
6. Review and refactor the design.

This ensures that every piece of code has a documented engineering reason behind it.

---

---

# Engineering Principles

DeskDog follows these core engineering principles throughout development:

* Build software around responsibilities rather than hardware.
* Separate application logic from hardware-specific code.
* Design modular and reusable components.
* Keep the architecture portable across hardware platforms.
* Document every significant engineering decision.
* Learn the concepts before implementing the solution.

---

# Learning Objective

DeskDog is more than a desktop companion.

It is a long-term journey into embedded software engineering, covering architecture, firmware development, graphics programming, system design, and professional engineering practices.

Every document in this directory represents knowledge gained while building the project.
